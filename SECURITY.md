# Security policy

## Supported code

Security fixes are maintained on the default branch. Older tags do not have a
separate security maintenance commitment; use the latest available release and
check whether a relevant fix has reached it.

## Reporting a vulnerability

Do not publish exploit details, credentials or personal data in public issues.
If GitHub's **Security → Report a vulnerability** option is enabled for this
repository, use it to send a private report. Otherwise, check the
[maintainer's profile](https://github.com/Hangell) for a private contact.
A dedicated security email has not yet been designated. GitHub abuse reports
are for platform abuse, not library vulnerability reports.

If neither private route is available, open an issue requesting a private
security contact without including vulnerability details.

Include the affected revision, Go version, a minimal reproduction, expected
and actual behavior, and an explanation of impact. Redact secrets. The
maintainer will assess the report and coordinate a fix and disclosure; there
is no guaranteed response time.
